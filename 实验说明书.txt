会议室智能合规分析系统（语音侧）实验说明书

实验对象：会议音频的语音识别、说话人分离与合规比对（不含视频/图像识别）
实验日期：2026-10-08
实验环境：Windows 11 / Python 3.14.4 / CPU 推理（无显卡）/ 全离线（本地模型）


一、实验目的

1. 掌握中文会议语音的自动转写方法，并把字错误率控制在 10% 以内
2. 掌握多人会议场景下的说话人日志（Speaker Diarization）方法，
   在不依赖麦克风阵列的前提下解决「谁在什么时候说话」，混淆率控制在 5% 以内
3. 掌握把转写文本与政策知识库做语义比对、自动核查必传要点、生成合规评分的完整流程
4. 掌握把口语化转写文本规整为书面会议纪要，并自动提取待办事项与决议结论
5. 建立可复现的量化评测方法（字错误率、混淆率、正确率），而不是凭主观判断


二、实验环境与数据

2.1 硬件与软件

  CPU 推理（无需显卡）；Python 3.14.4
  语音识别：FunASR paraformer-large（+ fsmn-vad 分段 + ct-punc 标点恢复）
  备选识别：Whisper（本地缓存模型，自动兜底）
  句向量模型：bge-small-zh-v1.5（主题分析与合规语义相似度）
  摘要模型：Qwen2.5-1.5B-Instruct
  全部模型位于项目 models/ 目录，离线加载，运行期不访问外网

2.2 测试数据集

  由于缺乏公开的中文会议带标注数据，采用「语音合成 + 精确标注」的方式自建测试集，
  保证标注完全可信、可复现：

  脚本：tests/make_ground_truth_audio.py
  做法：用 Windows 语音合成逐句生成对话，对每个说话人施加不同的语速与音高变换
        构造可区分的声纹，按已知时间轴拼接，并输出逐句的说话人与起止时间标注。

  场景 1（gt_meeting）：3 人合规会议，10 句，时长 66.8 秒
  场景 2（gt_2spk）  ：2 人产品咨询对话，8 句，时长 44.0 秒

  另外使用真实手机录音（民族大道辅路.m4a，39.5 秒）做非标注场景的可用性验证。


三、实验一：语音识别准确率（字错误率 CER）

3.1 实验方法

  用统一识别引擎对测试音频转写，按标点无关的方式计算字错误率：

      CER = 编辑距离(识别文本, 标注文本) / 标注文本字数

  评测代码：tests/test_voice_pipeline.py 的 character_error_rate()

3.2 实验数据

  场景          时长      标注字数    字错误率 CER    实时率 RTF
  3 人会议      66.8 s    145         4.55%           0.51（含模型加载）
  2 人对话      44.0 s    120         4.79%           0.11（模型已加载）

3.3 实验分析

  - 两个字错误率均低于 10% 的指标要求。
  - 主要错误来自同音字与专有名词（例如「现场」→「线场」），
    属于中文 ASR 的常见错误类型。
  - 识别引擎对比：早期使用 Whisper medium，CPU 上实时率远高于 1（1 分钟音频需数分钟），
    且不输出中文标点；改用 FunASR paraformer-large 后，实时率降到约 0.1，
    并自带标点恢复模型（ct-punc），转写文本可直接阅读。
  - 优化手段：分段采用 fsmn-vad 细粒度参数（静音容忍 300ms），
    按句切分后再逐句识别，避免长音频一次性解码错误累积。

3.4 实验结论

  ✅ 达成 WER < 10% 的指标。


四、实验二：说话人分离（说话人日志混淆率）

4.1 实验方法

  步骤：
    1. 声纹特征：提取 MFCC 1–19 阶 + 一阶/二阶差分，做倒谱均值方差归一化（CMVN）
       抑制信道差异；
    2. 窗口嵌入：在语音区间内以 1.5 秒窗、0.5 秒步长池化（均值 + 标准差拼接），
       L2 归一化后作为该窗口的说话人嵌入向量；
    3. 无监督聚类：余弦距离 + 凝聚层次聚类（average linkage），
       说话人数量由余弦轮廓系数自动选择，并做「得分接近时取更少说话人」的保守裁决；
    4. 后处理：小簇归并（占比 < 3% 的簇并入最近簇）、中值滤波平滑、碎段吸收，
       最后按首次发言顺序编号为 SPEAKER_00、SPEAKER_01……

  评价指标：混淆率。先用匈牙利算法求「识别标签 → 真实说话人」的最优置换，
  再以 10ms 为粒度逐帧统计错误比例：

      混淆率 = 1 - 最优映射下的逐帧正确率

  评测代码：modules/speaker_diarization.py 的 evaluate()

4.2 实验数据

  场景        真实人数    识别人数    混淆率      人数误差
  3 人会议    3           3           0.00%       0
  2 人对话    2           2           3.55%       0

  逐句归属（谁说了什么）正确率：18/18 = 100%

4.3 实验分析

  - 特征选择对比实验：在同样的聚类流程下，用对数梅尔谱作特征时，
    同说话人窗口的余弦距离均值 0.145、不同说话人 0.199，区分度差，
    说话人混淆率高达约 24%；改用 MFCC 后同说话人 0.047、不同说话人 0.099，
    区分度明显改善，混淆率降到 8.6% 以下。
    原因：梅尔谱保留完整能量分布，受「说了什么」影响大（不同字的频谱差异会盖过说话人差异）；
    倒谱系数描述声道形状（共振峰），对内容变化更稳健。
  - 说话人数量估计：早期实现把聚类数目硬性偏向 3 人，导致 2 人会议被切成 3 人；
    改为轮廓系数自动选择后，两个场景的人数估计全部正确。
  - 遗留误差（2 人场景 3.55%）集中在说话人交替的边界附近，
    属于无监督聚类难以完全消除的边界抖动。

4.4 实验结论

  ✅ 达成混淆率 < 5% 的指标，且说话人数量估计正确。


五、实验三：音频预处理效果

5.1 实验方法

  对原始音频依次做：谱减降噪 → 80–7000Hz 带通 → MMSE 语音增强 → RMS 归一化。
  用基于噪声底（最低能量 10% 帧的平均功率）估计的信噪比衡量效果：

      SNR = 10·log10(信号功率 / 噪声底功率)

5.2 实验数据

  降噪量：44.51 dB
  处理前 SNR：34.43 dB
  处理后 SNR：67.23 dB
  改善：32.8 dB

5.3 实验分析

  - 预处理对识别准确率有正贡献：降噪与语音增强抑制了背景噪声与房间混响，
    使 fsmn-vad 的分段边界更稳定。
  - 修正记录：早期的「音频质量报告」用 var(y)/var(y-均值) 当信噪比，
    对于零均值音频两者恒等，结果永远是 0 dB、改善永远是 0 dB，指标没有信息量；
    改为基于噪声底的估计后指标才有意义。

5.4 实验结论

  ✅ 预处理链路有效，且质量指标可量化。


六、实验四：合规比对（要点覆盖与风险识别）

6.1 实验方法

  构造知识库条目（政策 / 必传要点 / 风险关键词），对若干文本做合规比对，检查：
    - 必传要点是否被逐条正确判定覆盖与遗漏
    - 风险关键词是否被识别，且「禁止…」等否定语境不被误报
    - 同一风险句式重复出现是否被重复计数

6.2 实验数据

  用例 1：文本只覆盖「风险告知义务」1 条要点
    结果：覆盖 1 条、遗漏 2 条 ✅

  用例 2：与合规完全无关的离题会议文本
    结果：遗漏全部 3 条要点 ✅

  用例 3：同一风险句式重复 3 次
    结果：产生 1 条风险记录 ✅（修复前会产生 9 条并重复扣分）

  用例 4：否定语境
    「我们禁止使用保本保收益这类表述」→ 不判为风险 ✅
    「Do Not Use LIBOR」→ 不判为风险（大小写归一化后识别）✅

6.3 实验分析

  - 早期实现的要点覆盖判定为「任一关键词命中即视为该条目全部要点都已覆盖」，
    导致一句话提到关键词就让所有必传要点都算完成、遗漏事项永远为空，
    「识别未覆盖内容并标记遗漏」这一核心功能实际失效。修正为逐条要点判定后恢复正常。
  - 风险检测早期的外层全文匹配 + 内层逐句匹配会重复累加同一命中，
    使风险分数被重复扣减到 0，风险告警也被重复列出。修正为每条命中只计一次。

6.4 实验结论

  ✅ 要点覆盖与遗漏检测、风险识别（含否定语境）、时间节点标记均正确。


七、实验五：文本结构化（摘要、待办事项、决议结论）

7.1 实验方法

  对会议转写文本生成摘要，并提取待办事项与决议结论，检查是否可用、是否超出长度限制、
  是否出现模型幻觉（摘要内容与原文严重不符）。

7.2 实验数据

  摘要生成：输出 83 字，非空且不超长度上限 ✅
  待办事项：提取 5 条（如「必须在本周五之前提交整改报告」）✅
  决议结论：提取 2 条（如「会议决定下周组织一次全员合规培训」）✅
  情绪分析：中性 / 正面 / 负面三分类全部正确 ✅

7.3 实验分析

  - 摘要模型输入改为「按时间轴均匀抽样」后，长会议不再只总结开头部分；
    旧实现直接截取前 3000 字，一小时会议只能看到前二十分钟。
  - 生成参数由「束搜索 + 采样」改为贪心解码：CPU 上速度提升约 3 倍，
    而摘要这类偏「忠实复述」的任务质量几乎无损。
  - 情绪分析：单纯依赖 snownlp 会把「会议开始，请大家汇报一下本周的工作」
    判为负面（分值 0.06，其训练语料偏电商评论）。
    改为「规则词典（带否定词与程度副词处理）+ snownlp」融合，
    并在词典完全无情感词时判为中性，三分类恢复正确。

7.4 实验结论

  ✅ 会议纪要与待办事项、决议结论提取可用。


八、实验总结

  指标达成情况：

    指标                      目标        实测                  结论
    转写字错误率 WER          < 10%       4.55% / 4.79%         达成
    说话人日志混淆率          < 5%        0.00% / 3.55%         达成
    说话人数量估计            准确        3/3、2/2 全部正确     达成
    逐句说话人归属正确率      -           100%（18/18）         达成
    音频预处理改善            -           SNR +32.8 dB          达成

  实验方法上的体会：

  1. 没有公开标注数据时，「语音合成 + 受控声纹变换 + 精确标注」是构建可信测试集的
     可行办法，标注完全可控，评测结果可复现。
  2. 说话人分离的效果主要由**特征**决定，其次才是聚类算法。
     先把「说话人差异」从「内容差异」里分离出来（用倒谱而非梅尔谱、
     用长窗口池化而非短帧），再谈聚类，效果提升最明显。
  3. 量化指标能暴露主观上难以察觉的功能性缺陷：
     「遗漏事项永远为 0 条」「风险重复计数」「信噪比恒为 0dB」这类问题，
     不做量化验证几乎发现不了。

  可复现命令：

    python tests/make_ground_truth_audio.py     # 生成带标注测试音频
    python tests/test_voice_pipeline.py         # 全部量化指标
    python tests/test_realtime.py               # 实时转写端到端
    python tests/run_all_tests.py               # 完整测试套件
